# Providentia naming decision and public-launch due diligence

**Status:** Accepted by the project owner on 2026-07-29

**Official project and product name:** `Providentia`

## Decision

`Providentia` replaces `StockHome` as the official name and as the base for:

- repositories;
- PHP namespaces and Composer package naming;
- Dart packages, application identifiers, and generated client namespaces;
- contracts and schema identifiers;
- containers, deployment resources, monitoring labels, and documentation;
- future related project names.

The authoritative repositories are:

- `vast-development-method/providentia-laminas`
- `vast-development-method/providentia-flutter`

`StockHome` may appear only when a document explicitly identifies the
historical React/TypeScript PWA, its source evidence, or a former identifier
that requires a migration/redirect record.

## Consequences

1. New code and documentation use `Providentia`/`providentia` identifiers.
2. No new package, namespace, schema, environment variable, app ID, Compose
   project, or artifact name may use `stockhome` as its base.
3. Historical source paths, Git commit contents, and data evidence are not
   rewritten merely to hide the former name.
4. Durable product/home/entity IDs remain technical identifiers and are not
   coupled to display-name changes.
5. A later rename requires a new owner decision and a complete identifier,
   security, distribution, and migration impact review.

## Public-launch due diligence

The owner’s selection closes the naming decision. It does not constitute a
legal opinion, trademark clearance, domain acquisition, or app-store
reservation. Before public launch, record:

- target jurisdictions and relevant product/service classes;
- professional trademark/legal advice appropriate to those jurisdictions;
- approved Providentia domains and acquisition authority;
- app-store display names and stable bundle/package IDs;
- first-release locales and pronunciation/meaning review;
- repository, Composer, Dart, container, DNS, email, and social identifiers;
- impersonation, typosquat, phishing, and support-address controls;
- accepted residual legal/brand risks.

No automated search, domain availability result, or AI answer is formal
clearance.

## Privacy boundary

Public-launch research must not disclose receipt text, household product data,
home names, medical leaflet content, private images, or AI credentials.
Research records may contain public URLs and conclusions but no protected
handover media.

## Identifier reservation order

1. Complete legal/domain/app-store due diligence.
2. Acquire approved domains through authorized accounts with MFA and recovery.
3. Reserve bundle/package IDs and app-store records without premature
   publication.
4. Record canonical repository, package, container, DNS, email, and social
   identifiers.
5. Publish versioned Providentia design tokens/brand assets to both repositories.
6. Configure public/app/API host separation, cookie scope, CORS, CSP, deep
   links, email links, certificates, and update channels.
7. Run link, accessibility, metadata, authentication-host, installer, and
   update-channel tests.

## Historical-name handling

Former `StockHome` identifiers may be retained only where technically or
evidentially necessary:

- immutable source/Git history;
- source-package descriptions;
- controlled redirect or alias migration;
- legacy local-storage export provenance;
- audit/reconciliation records.

Any public alias or redirect requires an abuse, impersonation, legal, and
security review. It must not create a second active brand or weaken
authentication/cookie boundaries.

## Verification gate

Phase 1 passes the naming gate when both repositories prove:

- repository names match the accepted Providentia repositories;
- new code namespaces/packages/contracts use Providentia;
- generated artifacts contain no unintended `StockHome`/`stockhome`
  identifiers;
- historical-name occurrences are explicitly labelled as legacy evidence;
- documentation and Compose/CI identifiers use Providentia consistently.

Public launch additionally requires the due-diligence evidence listed above.
